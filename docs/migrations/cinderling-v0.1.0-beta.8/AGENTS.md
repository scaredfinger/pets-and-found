# Consumer operational guidance

Read docs/architecture/governance.md and relevant category compactions before implementation, and docs/consumer-installation.md before editing managed artifacts. Use compactions as implementation context and consult decision records only for scoped decision work. Assess every task for changes to governance, architectural rules or agent workflow and create a scoped draft when needed. A valid scoped draft is branch-authoritative and is not promoted architecture. Keep source comment-free and run pnpm test:arch, pnpm test, pnpm test:cinderling, pnpm lint and pnpm build. Decisions are draft-first; accepted decisions are immutable. Preserve the devcontainer nested mounts and host-owned authentication. Consumer source, package identity and implementation graph are project-owned.

For database-, browser-, container-, or service-dependent work, load the devcontainer-runtime skill first and read docs/runtime.md. Use the project's documented Docker, migration, browser, runtime:preflight and development-stack commands; verify readiness from the actual runner without exposing secrets or changing intentional mounts. This project has real acceptance and browser suites; run pnpm e2e:all on the reviewed candidate before merge. Load application-development-ports when creating applications or changing development ports and URLs; preserve the project's existing assignments. Clerk guidance applies only if the project chooses Clerk.

Cinderling is distributed as a private GitHub Release asset in scaredfinger/cinderling. For a consumer init or upgrade download, provide GH_TOKEN in the process environment with permission to read that repository; this project's own token or remote may not have access. If access is unavailable, stop and request authorized access. Do not print or persist the token. An already obtained release archive can be supplied with --archive. Read docs/consumer-installation.md for bootstrap and target-release upgrade instructions. Direct agent-operated GitHub REST requests follow the github-authentication skill; the consumer CLI uses GH_TOKEN separately.
