---
description: Select, review, and promote draft decision records
---

Discover direct Markdown files in `docs/decision-drafts`, excluding `README.md`. If there are no drafts, report that and stop. Use the question tool to offer **All drafts** or **Select drafts**. For **Select drafts**, use a multiple-choice question with one option per draft, showing its title and filename so the user can select without typing. If selection is cancelled or empty, stop without promoting anything. Do not require command arguments.

Read the selected drafts, `docs/decisions/template.md` and affected category compactions; consult only decision records needed for this promotion. Verify each selected draft's status, metadata, references and effects, including interactions between selected drafts. Ensure no direct edits to accepted decisions. Review each draft's authored `# Effective Architecture` section and its effects on existing compaction rules with the user, including a plan to reconcile superseded or contradictory prose; deterministic tooling cannot certify semantic agreement. Stop on unresolved contradictions or without explicit user approval to promote the selected drafts.

After approval, process selected drafts one at a time. Run `node tools/cli.mjs promote "<draft path>" --reviewed`; the tool writes the accepted record, index and appended compaction prose together. Before promoting the next draft, reconcile all affected compactions with the approved review, preserving source traceability and removing or qualifying superseded rules, then check their consistency and run `pnpm test:arch`. Stop on any promotion, reconciliation or check failure. If the record was already promoted, explicitly report it and the outstanding compaction work; report all earlier promotions and remaining drafts, since earlier promotions are not rolled back. After all selected drafts complete, run `pnpm test:tools` and report results. Commit only on user request.
